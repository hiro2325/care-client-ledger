# 介護利用者台帳（care-client-ledger）

居宅介護支援事業所の介護支援専門員（ケアマネジャー）が使う、利用者情報のマスター台帳です。ブラウザだけで動きます。

## 何を解決するか

同じ利用者の情報を、アセスメントシートにもケアプランにもモニタリング表にも何度も書き写しています。書き写すたびに手間がかかり、どれが最新なのか分からなくなります。

このアプリは、**情報の出どころを1か所にまとめる**ことを目的にしています。台帳に一度入れておけば、そこから各帳票へ受け渡せます。

## 公開URL

https://hiro2325.github.io/care-client-ledger/

## 動作確認の手順

1. 上の公開URLを開く
2. 「データ管理」タブを開く
3. **「ダミーデータを投入」**を押す
4. 「一覧」タブに戻ると、架空の利用者10件が表示される

ダミーデータには、認定期限が62日以内に迫っている人が3名、期限を過ぎている人が1名、状態が「終了」の人が1名含まれています。一覧の色分けと絞り込みがその場で確認できます。

試したあとは「データ管理」→「全データを消去する」で元に戻せます。

## 使い方

### 登録する

「新規登録」タブから入力します。利用者IDは `U0001` の形式で自動採番されるため、入力は不要です。性別・生年月日・要介護度が必須です。

生年月日は年・月・日の3つのプルダウンで選びます。利用者は80代・90代が多く、カレンダーで何十年も遡るのが大変なためです。

年齢と区分支給限度基準額は、入力した内容から自動で表示されます。

### 探す

「一覧」タブの上部で絞り込みます。

- **キーワード検索** — 主病名・現病・既往歴・特記事項・利用サービスを横断して探します
- **絞り込み** — 要介護度・状態・担当ケアマネを同時に指定できます
- **並べ替え** — 「認定期限が近い順」に並べ替えられます

認定期限が残り62日以内の行は黄色、期限を過ぎている行は赤色で表示され、「残り○日」が添えられます。状態が「終了」の人は色分けの対象外です。

行をクリックすると編集画面へ移動します。

### AI用テキストをコピーする

編集画面の下にある**「AI用テキストをコピー」**を押すと、次の形式のテキストがクリップボードに入ります。

```
【利用者ID】U0003
【基本】男性／88歳／独居
【介護保険】要介護2（認定期間 残り6か月）
【主病名】変形性膝関節症、高血圧症
【現病】糖尿病
【既往】大腿骨頸部骨折（2023年・右）
【自立度】障害高齢者 A1 ／ 認知症高齢者 Ⅰ
【ADL】移動:見守り 移乗:自立 排泄:自立 入浴:一部介助 食事:自立 更衣:自立
【IADL】調理:一部介助 買物:全介助 服薬:見守り 金銭管理:自立
【利用サービス】通所介護 週2回 ／ 福祉用具貸与（歩行器・手すり）
【本人の意向】自宅で暮らし続けたい
【家族の意向】長女：週末のみ支援可能
【特記】屋外歩行は歩行器を使用。雨天時の通所は送迎を玄関先まで。
```

これをAIに渡して、帳票の下書きを手伝わせます。個人にたどり着きうる項目は含まれません（詳しくは後述）。コピーする前に「コピーされる本文を確認する」から中身を目で確かめられます。

空欄の項目は、その行ごと出力されません。

### 印刷・PDF保存する

編集画面の**「印刷・PDF保存」**を押すとブラウザの印刷画面が開きます。A4縦1枚に台帳の全7区分が収まります。保存先に「PDFとして保存」を選べばPDFになります。

空欄の項目も枠だけ残るので、印刷してから手書きで書き足せます。見出しの横には氏名の手書き欄があります。

タブ・検索欄・ボタン類・画面下部の案内文は印刷されません。

### JSONでバックアップする

「データ管理」タブから行います。

- **書き出し** — 「JSONファイルに書き出す」を押すと `care-client-ledger-2026-10-01.json` のように日付入りのファイルが保存されます
- **読み込み** — 書き出したJSONを選ぶと復元されます。**今のデータはすべて置き換わります**
- **消去** — 「全データを消去する」を押すと確認が出ます。もう一度押すと消えます

**データはこのブラウザにのみ保存されます。** ブラウザの設定を変えたり、別のパソコンで開いたりすると見られなくなります。定期的にJSONを書き出して保管してください。

## 設計上の判断

### 利用者の氏名を持たない

台帳は利用者IDだけで管理し、氏名の欄を作っていません。IDと氏名の対応表はアプリの外（紙の台帳や事業所の既存システム）で管理します。

理由は、AIに情報を渡す使い方を前提にしているためです。氏名を持たない構造にしておけば、「出力するときに氏名を外す」という処理が不要になります。処理で外す方式は、書き忘れたときに漏れます。最初から持たなければ漏れようがありません。

### 認定期限の強調表示を62日としている

要介護認定の更新申請は、有効期間の満了日の2か月前から可能です。2か月は月によって日数が違い、**最大で62日前**にあたります。

60日で区切ると、申請できる期間の頭の2日を取りこぼします。「もう申請できるのに、一覧では目立っていない」という状態が生まれます。62日なら、申請可能になった初日から必ず色が付きます。

### AI連携エクスポートで個人にたどり着きうる項目を落としている

氏名を持たないだけでは足りません。項目を組み合わせると個人が絞り込めるためです。そこで次のように扱いを固定しています。

| 項目 | 扱い | 理由 |
|---|---|---|
| 生年月日 | 年齢に変換 | 生年月日は他の情報と突き合わせると個人を特定しうる |
| 認定期間 | 残り期間の概数に変換 | 日付は申請記録と突き合わせると個人を特定しうる |
| 保険者名 | 出力しない | 居住する自治体が分かる |
| かかりつけ医 | 出力しない | 医療機関から生活圏が絞り込める |
| 事業所名 | 出力しない | 利用者の生活圏が絞り込める |
| 担当ケアマネ | 出力しない | 事業所が絞り込める |

利用サービスは種別と頻度だけを出力します。

### AI連携エクスポートが「出すものリスト」方式である

出力の判断を、**出すものを列挙する方式**にしています。出さないものを列挙する方式は採りませんでした。

出さないものを列挙する方式だと、台帳に項目を増やしたときに書き忘れると、その項目は**そのまま出力されます**。書き忘れが即座に漏洩になります。

出すものを列挙する方式なら、書き忘れた項目は**出力されないだけ**で済みます。足りなければ気づいて足せますが、漏れた情報は取り戻せません。失敗したときにどちらに転ぶかで選びました。

実装は `src/lib/exportProfile.js` にあります。`EXPORTED_FIELDS`（出力する）・`EXCLUDED_FIELDS`（出力しない・理由つき）・`CONVERTED_FIELDS`（変換して出力）のどれにも無い項目は出力されません。分類し忘れた項目は `findUnclassifiedFields()` が検出して開発者に知らせます。

実際にこの仕組みが働いた例があります。初期版のコードが保存していた `createdAt` という項目が既存データに残っていたとき、ブラウザのコンソールに未分類として報告され、その項目は出力されていませんでした。

### 利用者を個別に削除する機能を作らない

介護保険の記録には保存義務があります。担当が終わったからといって消してよいものではありません。

担当終了は、状態を**「終了」**に変えて表します。終了した利用者は一覧に残りますが、認定期限の色分けの対象からは外れます。誤登録の修正は編集で行います。

全データの消去はデータ管理画面にありますが、これは動作確認やブラウザを明け渡すときのためのもので、1人ずつ消す機能ではありません。

### 印刷物には氏名の手書き欄を設け、保険者名なども出力している

アプリは氏名をデータとして一切保存しません。一方で、紙に出して訪問に持参したりファイルに綴じたりするときは、誰の台帳か分からないと使えません。

そこで印刷物には**氏名を手書きする欄**を設け、手元の対応表を見ながら人が書き込む形にしました。これにより、氏名がデジタルデータとして保存される場所はどこにも存在しないまま、紙としての実用性を確保しています。印刷してから手で書く一手間はかかりますが、その一手間がデータとしての氏名を持たない設計を成り立たせています。

あわせて、印刷物には**保険者名・かかりつけ医・事業所名を出力しています**。AI連携エクスポートでは除外している項目です。扱いを分けているのは、渡す相手が違うためです。エクスポートの渡し先はAIで、事業所の外へ出ます。印刷物の渡し先は事業所内の職員で、もともと利用者を担当している人です。担当者にとって保険者やかかりつけ医は訪問時に必要な情報であり、伏せる理由がありません。**出す相手によって出すものを変える**という判断です。

### localStorageの読み書きを storage.js に集約している

`window.localStorage` を呼ぶのは `src/lib/storage.js` だけです。画面側のコードからは直接触りません。

将来、保存先を IndexedDB やサーバーへ移すときに、差し替える範囲を1ファイルに閉じ込めるためです。画面のあちこちから localStorage を呼んでいると、移行のたびに全画面を探して直すことになります。

## 技術構成

React 19 + Vite 8 + JavaScript（TypeScriptは使用していません）。保存先はブラウザの localStorage のみで、データを外部サーバーへ送信するコードはありません。

```powershell
npm install
npm run dev        # 開発サーバー
npm run build      # 本番ビルド
npm run preview    # ビルド結果の確認
```

`main` ブランチへのプッシュで、GitHub Actions が自動的にビルドして GitHub Pages へ公開します。

## 今後の予定

- **呼称欄の追加** — 1000件規模になると、利用者IDだけでは一覧から目的の人を見つけにくくなります。氏名そのものではなく、本人を思い出せる短い呼称を持たせる方向で検討しています
- **ケアプラン・アセスメントシート・モニタリング表への情報連携** — 現在はAI用テキストのコピーまでです。各帳票の様式へ直接受け渡せるようにします
- **IndexedDBへの移行** — localStorage には容量の上限があり、件数が増えると行き詰まります
- **事業所内の複数端末での共有** — 現在はブラウザごとに別のデータです

## 掲載データについて

このリポジトリとアプリに含まれるデータは、**すべて架空のもの**です。利用者・担当ケアマネ・事業所・医療機関・保険者（自治体）の名称はいずれも実在しません。実在の人物・団体とは関係ありません。

スクリーンショットや説明文に出てくる内容も同様に架空の例です。
